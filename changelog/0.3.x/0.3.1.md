# 0.3.1 — 2026-11-01

## Added

- **`ioda_get_signals` accepts `source: "gtr"`** (Google Transparency Report traffic, unit `Traffic`, countries only). Region, ASN, and geoasn requests return an empty series with a notice naming countries as `gtr`'s only coverage (#22).
- **`IODA_CLAMP_LIMITS`** (default `true`). `false` rejects over-cap `limit`, `maxPoints`, `lookbackHours`, and `extendWindowSeconds` with `invalid_arguments` and advertises each cap as the schema `maximum`; an invalid value stops startup (#18).
- **Placeholder notices.** `ioda_search_entities`, `ioda_summarize_outages`, `ioda_find_outages`, and `ioda_get_alerts` name the page's IODA placeholder region rows (`[Invalid Region (N)]`, `Unknown Region in …`) (#20). `ioda_search_entities`, `ioda_get_signals`, and `ioda_get_status` flag an ASN row IODA answers with `attrs.ip_count` "0", meaning IODA holds no record of it (#19).
- **Archive-start notice.** An empty result whose window ends before IODA's 2022 archive start (detections 2022-01-26, `merit-nt` 2022-01-09, `bgp` 2022-01-18, `ping-slash24` 2022-02-02) says IODA holds no data that early instead of advising a code check or an earlier window; a window straddling a start gains one sentence (#23).
- **Trailing-null notice on `ioda_get_signals`.** It counts each series' not-yet-ended, pending, and missing trailing buckets against a publication allowance (1800 s; 10800 s for `merit-nt` and `gtr`) and advises ending the window at the allowance plus one bucket step before the call. An empty window that starts inside the allowance gets a publication-lag notice (#26).

## Changed

- **Count caps are served, not advertised-then-cut.** `limit` takes any value and serves at most 1000 (0.3.0 accepted 1–1000 and served at most 100); `maxPoints` serves at most 10000 (was 2000); `lookbackHours` serves at most 24 and `extendWindowSeconds` at most 1209600. Each schema drops its `maximum`, and a larger value is served at the cap with a notice. `limit` defaults to 20 and `maxPoints` to 200 (#18).
- **Strict mode is opt-in.** With `IODA_CLAMP_LIMITS=false`, `maxPoints` above 10000, `lookbackHours` above 24, and `extendWindowSeconds` above 1209600 are rejected (#18).
- **The 96 KiB combined response budget and `response_too_large` are removed.** The upstream body ceiling rises from 2 MiB to 4 MiB and now fails `upstream_schema` (#18).
- **`ioda_search_entities` `query` matches literally.** `%`, `_`, and `\` are escaped before the upstream call, so `%` no longer lists the whole type; a query pre-escaped as `Telegram\_Messenger` now matches the literal backslash, so drop manual escapes (#25).
- **`ioda_get_alerts` description** says a recovery's `historyValue` can be a baseline IODA re-based during a long event; the `ioda-outages-guide` skill's gates 5 and 8 judge recovery against the detection's `historyValue` and treat long events as possible level shifts (#24).
