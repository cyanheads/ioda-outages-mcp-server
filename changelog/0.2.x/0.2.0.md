# 0.2.0 — 2026-10-21

## Added

- **`ioda_summarize_outages`** ranks countries, regions, ASNs, or geoasn entities by IODA's outage scores over a window, in descending `scores.overall`, relayed unchanged. Narrow it with `entityCode` or a `relatedTo` scope. (#6)
- **`relatedToType` and `relatedToCode`** on `ioda_search_entities`, `ioda_find_outages`, `ioda_get_alerts`, and `ioda_summarize_outages` limit results to `entityType` entities within one entity, such as the regions of a country; a scope without `entityType`, with `entityCode`, or with `page` above 0 on alerts fails `invalid_scope`. (#5)
- **`geoasn` entity type** (one ASN within a region or country, such as `40934-576`) is accepted by every tool that takes an `entityType`; `ioda_search_entities` returns object-form `subnames`. (#7)
- **`unit`** in `ioda_get_signals` `semantics` and in each `ioda_get_status` `signals[]` entry reports IODA's published unit for the source. (#8)
- **`pendingCount`** on `ioda_get_status` series summaries counts trailing buckets still inside the publication allowance. (#4)

## Changed

- **Over-cap numeric inputs** are served at the cap with a notice instead of rejected: `limit` up to 1000 (served 100), `maxPoints` up to 20000 (served 2000), `lookbackHours` up to 240 (served 24), `extendWindowSeconds` up to 12096000 (served 1209600). (#9)
- **Rejections** carry specific reasons: `invalid_source` for unsupported sources, `invalid_query` for over-length search queries, `invalid_scope`, and a distinct `invalid_window` message per broken rule, replacing generic argument errors. (#9, #5)
- **`content[]` JSON blocks** render arrays of numbers and nulls on one line, such as `series[].values`; the parsed blocks still equal `structuredContent`. (#10)

## Fixed

- **`ioda_get_status` for an unknown country or region code** fails `entity_not_found` where it returned `detection: "none_returned"` beside three failed signal components. (#3)
- **`ioda_find_outages` without `entityType`** defaults `extendWindowSeconds` to 86400 (1209600 with `entityType`), echoed in `applied` with a notice, so hour- and day-long global windows answer instead of timing out; global windows of several days can still time out, and the `upstream_timeout` recovery names a narrower window, a smaller `extendWindowSeconds`, or an `entityType` filter. (#2)
- **`ioda_get_status` freshness** counts a trailing null inside the 1800-second publication allowance as pending rather than missing, and reads a latest bucket within that allowance as `recent`. (#4)
